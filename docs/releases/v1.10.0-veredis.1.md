# Codex Usage Monitor v1.10.0-veredis.1

This is the first major update of the veredis fork since v1.9.1-veredis.7. It brings in the polling and appearance work of upstream [v1.10.0](https://github.com/upstream-ray/codex-usage-monitor/releases/tag/v1.10.0), and adds fork-specific reliability, Claude, MCP and installation improvements. Settings from earlier versions carry over.

## Install or upgrade

- **Portable:** download `codex-usage.exe` and run it.
- **Installed:** download `install.ps1` and run:
  ```powershell
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
  ```
  It installs to `%LOCALAPPDATA%\Programs\CodexUsage` per user, verifies the SHA-256 and keeps your settings.
- **Existing installs** are offered this release by the in-app updater.

This fork updates only from `veredis/codex-usage-monitor`. The WinGet package `Ray.CodexUsage` is upstream's.

## Reliability

- **Independent providers:** each provider is polled on its own schedule and worker, with its own backoff, so one provider's slow responses or rate limits never delay or stale-mark another.
- **Server deadlines:** a server `Retry-After` deadline is honoured, even by **Refresh**.
- **Claude spacing:** Claude usage requests are spaced at least 2 minutes apart, because the endpoint is shared with Claude Code's status line.
- **Recovery:** a refresh runs about 10 s after resume from sleep, and when internet access returns.
- **Stale values:** the last values persist across restarts and are marked stale (`!`) until refreshed. A failing provider keeps its last value, marked `!`.
- **At a quota reset:** the last value stays for up to five minutes, marked `!` and without a countdown, until the new one arrives. It is never shown as a guessed 0% or 100%.
- **Missing windows:** `--` means a window the provider does not report; `!--` means the reset passed and the new value is not known yet.
- **Logging:** bounded operational logging at `%LOCALAPPDATA%\CodexUsage\logs` without tokens, credentials or prompts.

## Authentication

- **No model use:** the monitor never starts a model request to recover authentication. It never runs `claude -p` or the Messages API, and its `codex exec` recovery path is disabled.
- **Claude:** the monitor never refreshes Claude OAuth tokens and never writes Claude credentials. When a sign-in expires, it waits for Claude Code or Claude Desktop to renew their own sign-in.
- **Codex:** after repeated authentication failures, the monitor may ask the official Codex app-server to renew Codex's own sign-in. This is model-free (`account/read` with `refreshToken`); Codex performs the renewal and stores its own credentials.

## Claude

- **Cached reading:** Claude Code's own cached usage reading is used when it is under two minutes old and belongs to the same account, so no request is made.
- **Optional Claude Desktop fallback, off by default:** when the CLI sign-in has expired, the monitor can use the Claude desktop app's sign-in for the same account, read-only. Turning it on asks for confirmation and explains what is read and sent. The token is held in memory only for the request.

## Appearance

- **Upstream's appearance options:** antialiased rounded bars (continuous or segmented, standard or slim), standard or larger text, and high-contrast dark and light palettes with a solid backdrop.
- **Two profiles:** **Solid Dark** (for translucent taskbars) and **Taskbar Blend** (the standard look).
- **Colors:** default per-provider colors (Claude orange, Codex green, Antigravity blue), or your own (one for all bars, the Windows accent, or one per provider), with a reset.
- **Provider icons:** optional (**Appearance > Show provider icons**).
- **Spacing:** one spacing system across labels, icons, bars, percentages and countdowns, with each provider's column sized to its own values.
- **Hover popup:** shows the exact local reset time, or what `--`, `!` and `!--` mean. It is dark or light to match the widget, click-through, and never takes focus.
- **Context menus:** dark or light to match the widget.
- **Display modes:** Default (Mixed), Used or Remaining.

## Windows integration

- **Start with Windows** registers the stable installed copy, quoted, and the installed copy repairs a registration left pointing at an older executable.
- **Taskbar placement:** the widget stays left of the notification area; the chosen taskbar is remembered per display; it recovers when a display disconnects or Explorer restarts.

## MCP (optional)

An optional loopback-only MCP server at `http://127.0.0.1:46827/mcp` provides two read-only tools, `get_codex_usage` and `get_claude_usage`.

- **Cached:** they return the latest cached snapshot with freshness and `data_source`.
- **No side effects:** a tool call never polls a provider, reads credentials or starts a model task.
