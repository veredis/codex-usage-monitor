# Codex Usage Monitor v1.10.0-veredis.2

A reliability update to v1.10.0-veredis.1. It shows the same Antigravity quota as Antigravity itself, and improves reset handling, near-zero quota and taskbar placement. Settings from earlier versions carry over.

## Install or upgrade

- **Portable:** download `codex-usage.exe` and run it.
- **Installed:** download `install.ps1` and run:
  ```powershell
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
  ```
  It installs to `%LOCALAPPDATA%\Programs\CodexUsage` per user, verifies the SHA-256 and keeps your settings.
- **Existing installs:** the in-app updater offers this release.

This fork updates only from `veredis/codex-usage-monitor`.

## Antigravity

- **The full quota, as Antigravity's panel shows it:**
  - While Antigravity is open, the monitor reads quota from Antigravity's own local language server.
  - That covers Gemini Models, Claude and GPT models, and Gemini 4 Argon, each with its own 5-hour and weekly windows.
  - Before, the monitor used only Google's quota service, which reported just "Claude and GPT models" for some accounts.
  - Google's service remains the fallback when Antigravity is closed.
- **Choose the group:**
  - **Models > Antigravity quota** offers **Auto**, which shows Gemini Models first, or any group Antigravity reports.
  - The hover popup names the group shown.
  - A window the group does not have shows `--`. For example, Gemini 4 Argon has a weekly limit only.
  - A chosen group that the current source does not report keeps its last value, marked `!`, and is never replaced by another group's values.
- **Local key:** the temporary local key comes from the command line of Antigravity's bundled server, which is checked by its install path.
  - It is sent only to that process on `127.0.0.1`.
  - It is never logged or stored.
  - Its other tokens are never used.
- **Expired sign-in:** when the stored Antigravity sign-in has expired, the monitor sends Google no requests until Antigravity renews it.

## Resets

- **Claude Code's cached reading:** it is no longer used once a reset has passed since it was read. A pre-reset value can no longer replace a fresh request.
- **Request timing:** a regular Claude request due less than a minute before a known reset now runs just after the reset. This adds no requests.
- **Reset times:** times with a time-zone offset (`+hh:mm` or `-hh:mm`) are now read correctly.

## Near-zero quota

- **Percentages:** a remaining quota above 0% but below 1% shows as `<1%`, and one just below 100% shows as `99%`. So `0%` and `100%` mean exactly empty and exactly full.
- **Alerts and Credits:** alerts and the **When needed** Credits display react to actual exhaustion and exact thresholds, not to rounded percentages.

## Taskbar

- **Brief wrong tray readings:** Windows sometimes briefly reports the notification area's edge in the wrong place, or not at all. The widget now waits for a second reading 750 ms later before making a large move.
- **Normal changes still apply at once:** tray growth, a new taskbar and taskbar size changes are applied immediately.

## Display

- **No data at all:** a provider that has never returned data now shows empty bars with its status label. Before, it showed full bars that looked like 0% used.
- **Restored values:** an Antigravity value saved by an earlier version without a group name is no longer restored. This prevents showing an old value under the wrong group.

## Field status

- **Confirmed in use:** the Antigravity local-server reading matched Antigravity's own panel for all three groups, and group selection works.
- **Covered by tests, not yet seen in the field:**
  - The Claude reset timing, until a natural 5-hour reset is observed with this version.
  - The taskbar fix: the brief wrong readings were found in logs, but the intermittent jump has not recurred since.
